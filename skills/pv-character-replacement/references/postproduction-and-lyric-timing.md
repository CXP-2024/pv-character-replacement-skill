# 无字素材包与逐字歌词时间轴

仅在用户要求后期素材、去字版或歌词对齐时使用。先核定最新正式成片、配套素材和音频，避免对旧预览制作整套交付。正式更新规则见 [review-and-delivery.md](review-and-delivery.md)。

## 从制作阶段保留信息

能分层时保留无字角色/背景底图、文字层、独立道具/特效和源曝光表。字体、字号、文本原始换行/空格、坐标、行距、淡入淡出及逐字高亮从实际合成参数保存，不在导出后凭 OCR 重新猜测。

已烧录在视频中的字可能没有原始字体或排版参数。区分 `source`、`measured`、`estimated` 和 `unknown`；未知值用 null 或清晰说明，不能把估计宣称为原始数据。右下角标志/签名等是否保留，以用户指定的保护范围为准。

## 无字版与素材包

1. 记录最终版文件、哈希及 ffprobe 的宽高、像素宽高比、帧率/时间基准、帧数/PTS、视频与音频时长、音轨参数。区分容器时长与音视频流时长，不能只比四舍五入的总秒数。
2. 优先由对应无字底图重新合成。只有烧录文字时，逐一列出文字区域与实际独立绘稿，选择正确底层素材恢复或用生图模型去字；用户明确要求逐关键稿生图时照做。批量输入要固定身份/画风，明确只编辑字与它遮住的背景或线稿。参考图不能把后续歌词误带回结果。
3. 用文字编辑区和受保护区域检查结果：人物、场景、构图、水印、镜头运动及原独立特效保留；不能因为去字把背景清空或重置角色。普通合成不等于允许程序重画；图像编辑仍遵循可用生图工具的规则。逐稿生成检查后再按原曝光合成，不把特效更新降成绘稿帧率。
4. 复制原音轨时尽量流复制，保持起点和封装中的时间偏移；不要重新拉伸或按歌词长度截短。视频帧映射和时间轴保持一致。重建过的区域与压缩编码均可能产生像素差异，不能承诺生成式去字做到全图像素锁定。
5. 素材按原文件复制到用户约定目录，不移动、不重压缩原图。清单区分原图、采用图、掩膜与图层用途，记录画布、素材尺寸、时间区间、缩放、位置、锚点、层级及动态变换。重复曝光仍需列明各次区间；源码没有的可编辑图层或字体不能伪造。
6. 导出歌词清单与 SRT 时保留原始显示文本和 ID。每条记录出现/消失时刻、像素坐标及其画布分辨率、排版参数、字级高亮范围/颜色/时刻与淡入淡出；先把“沃”等用户指定的文字替换规则作用到显示清单，再与实际成片核对。SRT 不能承载的样式和字级效果保存在 JSON。

只有存在且适合交付的实际字体文件才附在字体目录；未知或不能提供的内容写入说明。草稿、模型缓存、旧版本与备份放在交付目录之外。用户指定只新增文件时不覆盖任何已有文件。

## 无字版验收

- 用 ffprobe 核对双方的尺寸、帧率/PTS、帧数、总时长和音轨；新编码应完成整段解码。音频优先检查复制后的数据与时间戳，重新编码时不能用哈希相等作为预期。
- 检查每个原有文字区间至少一张有效显示帧，并覆盖开场、逐字变色、淡入淡出、转场和尾声。OCR 只负责找候选残字，不能替代看图，也不能把需保留的水印当残字。
- 抽查保护区、背景与人物；检测整帧白/黑或异常平坦画面，并对照原作，避免误报本来就有的闪白。全片技术解码加关键帧看图，分别报告各自范围；没有逐帧看图就不要声称逐帧无残留。
- 查看成片实际编码 profile/pix_fmt，并尽可能在目标播放器播放。ffmpeg 可解码不保证桌面播放器显示正常；兼容性规则见交付参考文件。

## 已知歌词的逐字强制对齐

### 输入与时间基准

- 将正式音轨与显示歌词冻结为本次输入，记录哈希、模型/工具版本、方法、采样率及任何起始偏移。音频文件零点未必等于视频零点，先验证同步；不能仅因二者总时长接近就当作对齐。
- 保留显示 `text` 与每字索引，另建实际演唱文本。去掉空格、换行及未唱出的标点；跳过未演唱的署名和标题，但不能仅凭它叫“标题”就跳过实际唱出的歌名。显示用字与发音不同（如谐音替字）时记录映射，输出仍对应显示字符。
- 同一时间窗口的多行歌词先确定实际演唱顺序。不能把同一段人声分别强制对齐到两句而产生重复时间；必要时合并音频窗口对齐后按原条目 ID 拆回。重复句保留各自窗口。
- 按用户指定窗口裁切，例如 `[max(0, start - 0.5), end]`。输出时间为裁片内时间加窗口起点、再加核定的视频偏移；避免加两次偏移。若窗口切掉起音/尾音，标记低置信度并说明，不能擅自改已批准的字幕曝光。

### 方法与质量门槛

1. 用户指定 Demucs 时使用所指定模型与选项，例如 `htdemucs --two-stems=vocals`，保存人声 WAV；重采样仅为对齐模型输入，不改变音频速度或视频音轨。模型与缓存不混进素材交付包。
2. 优先执行用户指定的已知文本对齐。中文使用 MMS_FA 时可将每个汉字用 pypinyin 转成无声调拼音，保留字到拼音/token 的映射，结合上下文校核多音字。拼音内 token 的起止合并成一个汉字的区间，不把拼音字母当汉字。先验证本机 torchaudio 版本是否提供该接口/模型，勿默认最新版一定可用；依赖变更放入独立环境。
3. 首选不可用或结果质量明显失败时，尝试用户允许的备用方法（例如 stable-ts align）。工具能跑完不代表对齐成功：多数行低置信度、系统性贴窗口边界、长串挤成极短字、或留白中也被分配歌词时，检查文本、窗口、同步和分离结果，再用另一方法复核代表性片段。不要靠平均分字或调低阈值冒充强制对齐。
4. 保留原始精度做判断，序列化时按用户要求保留两位小数。对齐分数只能作为所用模型的启发式指标，不能宣称为校准概率或与另一模型直接比较。阈值、聚合方法、缺失评分及标记原因写入报告。
5. 用户未另定标准时，将低分、缺字、顺序异常、区间越界、明显贴边或时长异常标记为需复查。用户指定 `<0.05 秒` / `>2 秒` 时按该标准标记；真实长音也标记供确认，不强行缩短。舍入后零时长或重叠另行标明；不同字不能因为修数字而失去真实起音。
6. 对低置信度、重复句、快唱与长音做代表性试听/波形核对；无法试听时明说。备用方法失败、不可用或也不可信时仍可交付草稿及原因，不把运行成功当作最终质量通过。

### 输出约定

用户给定结构时保持它。例如 `char_timing.json` 的一条待复查结果：

```json
[{"id": "l04", "chars": [{"char": "最", "start": 43.31, "end": 43.62}], "low_confidence": true}]
```

每字包含 `char`、`start`、`end`；任一字需复查时在所属条目标记 `low_confidence: true`。更细的分数、字索引、实际演唱映射、原因和方法写入独立报告，避免破坏消费者约定。

交付说明实际采用的主/备用方法、低置信度条目 ID、是否做过试听，以及未能解决的限制。只新增的任务要验证既有文件未变；若后来只修画面且音频/时间映射未变，保留已有歌词时间轴，不重复跑对齐或覆盖它。
